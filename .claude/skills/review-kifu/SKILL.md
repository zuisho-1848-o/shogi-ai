# 棋譜レビュー

## 手順

1. 引数のKIFパス（なければユーザーに貼られた棋譜本文を `kifu/<日付>.kif` に保存）を確認する。
2. 解析を実行（初回は1局あたり数分。キャッシュあり、再実行は速い）:
   ```bash
   cd /Users/zuisho/Documents/highsto/claudeその他/shogi-ai
   .venv/bin/python -m kifu_review <kif> --me <自分の対局者名> --movetime 1500 --fv-scale 24
   ```
   - 自分の名前が不明なら先に1度だけ聞く（`KIFU_REVIEW_ME` 環境変数に入れておくと次回から不要）。
   - 評価関数 `engines/yaneuraou-std/eval/nn.bin` が無いというエラーなら `engines/README.md` の手順を案内する。
3. `reports/<ファイル名>/report.md`（と `report.json`）を読む。
4. 振り返るべき手ごとに、下の型で解説する。**レポートの数値・読み筋・自動所見を根拠にし、読み筋に無いことを断定しない**。盤面図は必ず見て、駒の配置を確認してから語る。

## 解説の型（1手あたり）

- **何が起きたか**: 指した手 → 評価値の変化（形勢が何から何へ）
- **なぜ悪いか**: 相手の最善進行（refutation_pv）で実際に何が起きるか。駒損・詰み筋・攻めの切れ・玉の薄さなど、読み筋で確認できる具体的な理由
- **最善手の狙い**: best_pv を追って、その手が何を狙い、どんな構想につながるか
- **次回の考え方**: 同種の局面で指す前に確認すべき一言チェック（例:「相手の飛車の利きに駒を動かす前に、その駒が取られないか見る」）。時間タグ（即指し/長考）があれば絡める
- 形勢がほぼ変わらない手（差が小さい）は「差は小さいが選び方の傾向」として軽く触れる

## 最後に

- 全体の傾向（序盤/中盤/終盤どこで崩れたか、悪手の共通パターン）を3点以内でまとめる
- 次の対局で意識する1〜2点だけを提示する（多すぎない）
- 駒得・詰みなどの自動所見が怪しい（PVが短い等）場合は、`--movetime 5000` で対象局面を再解析できると提案する
